# Конвейер: от выбора темы до влитого в main релиза

Канал **The Universe Inside Out** — весь космос (планеты, луны, звёзды, чёрные дыры, галактики, экзопланеты, кометы,
реальные миссии и события, масштабы, «что если»): реальные объекты + реальные числа + кинематографичный рендер
Blender. **Только EN** (`languages: ["en"]`), **≤ 30 с** (`docs/shorts_format.md`). Планка картинки — `docs/quality.md`.

Человек запускает и решает три раза: **`/next-video`**, **`/make-video N`** (выбор темы) и **«ок»** (одобрение
сценария, hero-кадров и чернового видео, `docs/approval.md`). Всё остальное делает агент — Claude Code или Codex — по
скиллам `.claude/skills/` = `.agents/skills/` (можно словами: «предложи следующее видео», «делаем вариант 2»).
Роли (исследователь, фактчекер, постановщик, критики) — `docs/workflows.md`; библиотека — `docs/spacekit.md`;
время и ETA — `docs/timings.md`; очередь рендера — `docs/render_queue.md`; правила агентов — `AGENTS.md`.

```
[ТЫ] /next-video  (новый чат в основной копии)
   └► video_wt.py start → worktree out/wt/epNNN, ветка video/epNNN
      → 3 варианта с money shot (ideas/<дата>_options.md) → коммит → стоп
[ТЫ] /make-video N [+ правки]  (тот же чат)
   └► claim <slug> → факты → визуальный бриф → сценарий → сцена/шоты
      → превью тайминга → hero-кадры 100 % → критика «Кино/вау» и др. → черновое видео → стоп
[ТЫ] «ок» / правки
   └► submit final → очередь: кадры → framecheck → звук → монтаж → QA → release
      → визуальный QA (accept) → тебе: мастер MP4 + publish_en.md
      → учёт → video_wt.py finish: main в ветку → тесты → ff main → remove worktree   = DoD
```

## Чаты и worktree

Один ролик = один чат = одна worktree = одна ветка. Параллельно идут несколько роликов и задач, в том числе
у Claude и Codex одновременно; основная копия общая и не правится (`AGENTS.md`, «Работа агентов»).

| Команда (`python tools/video_wt.py …`) | Где | Что делает |
|---|---|---|
| `start` | основная копия | резерв номера `refs/video/epNNN` (create-only: два чата не получат один номер; номер не переиспользуется), worktree `out/wt/epNNN` на ветке `video/epNNN` от main, копия игнорируемых ассетов |
| `start --task <slug>` | основная копия | то же для не-ролика: `task-<slug>`, ветка `task/<slug>` |
| `start --here` | worktree от приложения | резерв номера и переименование текущей ветки в `video/epNNN` |
| `claim <slug>` | worktree ролика | ветка → `video/epNNN_<slug>`; папка эпизода — `episodes/epNNN_<slug>/` |
| `status` | где угодно | все worktree: ветка, чисто/грязно, коммиты впереди main, release; резервы; следующий номер |
| `finish [--no-release]` | своя worktree | DoD: чистое дерево, release (мастер + `publish_en.md`), финал принят в очереди (`accept`), нет живых заданий → `git merge main` в ветку → `check_episode` + тесты → `git merge --ff-only` в основной копии (только если она на `main`) → `out/<ep>/` переносится в основную копию |
| `remove <имя> [--abandon] [--drop-out]` | основная копия | удалить влитую worktree и ветку; `--abandon` — только worktree, невлитая ветка остаётся; worktree с `out/ep*` (кадры, мастер) — только с `--drop-out` |

- Claude входит в worktree `EnterWorktree` с путём из `start` и выходит `ExitWorktree` (keep) перед `remove`;
  Codex работает с `workdir` = путь worktree. Чат по ролику открывать в основной копии.
- Worktree — в `out/wt/` основной копии: внутри папки проекта, куда пишет песочница Codex (`workspace-write`), и
  вне git (`out/` в `.gitignore`). Claude в ней читает и родительский `CLAUDE.md` основной копии: при расхождении
  правила main новее — `git merge main` в свою ветку.
- Worktree, созданная приложением (`start --here`): после `finish` её не удалять — она чистая и влитая, приложение
  уберёт её при архивации чата; в ответе так и сказать.
- Старые worktree (`out/w8`, `out/w9`, `../ss-ep005`, ветки `codex/…`, `ep005_…`): `finish` находит эпизод по папке
  `episodes/epNNN_*` в диффе с main и проверяет тот же DoD; `remove` не удалит их `out/<ep>/` без `--drop-out`.
- В worktree нет `.venv` и весов TTS: очередь берёт их из основной копии сама, из какой бы копии ни вызвали
  `tools/render_queue.py`; путь к venv для прочих скриптов печатает `start`.
- Очередь общая (`out/q` основной копии). Во время задания кадры и логи — в снимке (`snapshot` из
  `render_queue.py status --json`); в `out/<ep>/` своей worktree результаты попадают по завершении задания.
- `finish` не прошёл — причина в выводе: закоммитить, решить конфликт в своей worktree, дождаться задания, повторить.
  `main` сдвинулся между проверками — просто повторить.

## Этап 1. `/next-video` — варианты следующего ролика

Агент заводит worktree (`start`), читает `docs/channel.md` (серии, темы, ✅), `episodes/INDEX.md` (что и какими
шотами снято), `docs/quality.md`, `docs/spacekit.md`, `docs/timings.md`, `docs/metrics.md`, `docs/competitors.md`,
отметки «Выбран» в `ideas/*_options.md` и `video_wt.py status` (что снимают другие чаты). Пишет
`ideas/<YYYY-MM-DD>_options.md` по `ideas/_TEMPLATE_options.md`: **3 варианта** — один = следующая неотмеченная
тема из `docs/channel.md`, два — из других серий. По каждому:

- объект (каталожное имя), крючок первой секунды (фраза + кадр), **money shot**, вау 1–5, 2–3 визуальных референса;
- 4–6 ключевых фактов с источниками (ATNF, NASA Exoplanet Archive, JPL SSD/Horizons; статьи; страницы миссий);
- план шотов (что нового по визуалу относительно `episodes/INDEX.md`);
- что добавить в `spacekit` (матрица `docs/spacekit.md`), оценка работы (ч) и рендера (ч GPU, план 4–6 ч);
- риски (спорные факты, сложная визуализация).

Коммит в ветке ролика. **Ты отвечаешь: «/make-video 2»** (можно с правками: «2, но без кольца, и хук про
скорость»). Выбор и правки дописываются в конец того же ideas-файла.

## Этап 2. `/make-video` — производство до одобрения

После каждого блока — коммит (`AGENTS.md`, «Работа агентов»).

1. **Эпизод.** `video_wt.py claim <slug>`, `episodes/_template/` → `episodes/<ep>/`.
2. **Факты.** Исследователь + фактчекер (`docs/workflows.md`) → `facts.md` с источниками и визуальными референсами.
3. **Визуальный бриф.** Постановщик → `visual_brief.md` (первый кадр, money shot, палитра, свет, камера и событие
   каждого шота, условности, бюджет); критик «Кино/вау» — до кода шотов.
4. **Сценарий.** `script_9x16.json`: 6–8 фраз EN с якорями во времени (цель 29–29,5 с, жёсткий максимум 30,0 с;
   55–70 слов); факт-крючок в первой фразе, «likely/probably» для гипотез, финальная фраза подводит к петле.
5. **Сцена и шоты.** `system.py` (реальные параметры → экранный масштаб, условности — в docstring), новые модули
   `spacekit/` при необходимости (+ регресс эп. 001 через `tools/imgdiff.py`); `shots_9x16.py` по брифу и
   `docs/quality.md` (6–10 шотов по 2–5 с, глубина, свет, движение, оптика); `episode.json` (Σ кадров монтажа ≤ 1799 при
   60 fps — AAC округляет звук вверх, 1800 кадров → дорожка 30,016 с). `python tools/check_episode.py …`.
6. **Превью тайминга.** `render_queue.py submit preview … --with-tts`: все шоты pct=50 → контактный лист +
   черновая озвучка (нет OVERRUN). Cue-лист музыки — по логам превью (FLASH печатается и там, см. ниже).
7. **Hero-кадры.** `submit preview … --hero` по шоту: 100 %, сэмплы из кода шота → `out/<ep>/9x16/hero/` и
   `sheet_hero.png` (`docs/quality.md`, «Ворота»): по ним судят картинку и считают с/кадр; сэмплы и эффекты — под
   финал 4–6 ч.
8. **Критика** (`docs/workflows.md`): «Кино/вау» до 3 раундов (шот ≥ 8/10), остальные — до 2 → правки → 6–7.
9. **Черновое видео** целиком (`docs/approval.md`, 1a); не собралось — одобрение без него.

**Ты получаешь сообщение по шаблону `docs/approval.md` (hero-кадры + черновое видео) и отвечаешь: «ок» или
правки.** После «ок» — до DoD без вопросов, кроме случаев остановки из `docs/approval.md`.

## Этап 3. После «ок» — финал, релиз, влитие

10. **Рендер.** `python tools/render_queue.py submit final episodes/<ep>/episode.json --approved 'одобрение из чата'`.
    Заранее готовы cue-лист и `publish_en.md`. Очередь выбирает свободный ПК, фиксирует его за эпизодом и выполняет
    финал порциями по 120 кадров; между ними проходят приоритетные превью. Шаги 11–14 очередь делает сама, без
    присутствия модели. Статус — `render_queue.py status --json`. Время — по `docs/timings.md` с учётом повторной
    сборки сцен. Все кадры — `tools/framecheck.py` (см. «QA»): PASS до звука и сборки.
11. **Звук.** `tools/tts.py` (Kokoro) → `tools/music.py` по согласованному cue-листу → `tools/mix.py` (−14 LUFS,
    true-peak ≤ −1 dBTP).
12. **Монтаж** — одна сборка, мастер EN: `tools/build_edit.py <episode.json> en` → `editkit/assemble.py`.
    MP4 H.264 1080×1920p60 40 Мбит/с + AAC 320 кбит/с 48 кГц. Копии `--light`/`--preview` не собираются (пакет —
    мастер + md, `docs/publish.md`).
13. **Машинный QA.** `python tools/qa.py episodes/<ep>/episode.json en` — PASS/FAIL (см. «QA»).
14. **Пакет к загрузке** (`docs/publish.md`): `python tools/release.py episodes/<ep>/episode.json` → `out/<ep>/release/`
    (мастер MP4 и `publish_en.md`); задание → `needs_review`.
15. **Визуальный QA** агентом: PNG `qa_en/` и мастер не хуже hero-кадров → `render_queue.py accept JOB`.
    Тебе приходят оба файла. Загрузку делаешь ты (Studio); автозагрузка через API — позже (`docs/publish.md`).
16. **Учёт и влитие.** INDEX, README, ✅ в channel, замеры в timings, уроки в доки → коммит →
    `video_wt.py finish` → `remove`. Это и есть DoD ролика.

### Оговорка про контейнер (faststart, BT.709)

В Blender 5.2 у `FFmpegSettings` нет `movflags` и цветовых тегов: MP4 выходит без faststart (moov в конце) и без
тегов BT.709; аудио 320 кбит/с ниже рекомендованных YouTube 384 (research.md:210, 278, 298). YouTube такие файлы
принимает — **сейчас сознательно идём без ремукса**. Если появится ffmpeg (`winget install Gyan.FFmpeg`), финальный шаг:
`ffmpeg -i in.mp4 -c copy -movflags +faststart -bsf:v h264_metadata=colour_primaries=1:transfer_characteristics=1:matrix_coefficients=1 out.mp4`.

## Музыка по событиям (FLASH → cues)

- Шот с пульсаром печатает `FLASH <шот>: кадр:значение, …` (номера кадров шота, `spacekit.shot.report_flash`).
  Другие события (проход планеты, вспышка магнитара) — строки `EVENT <шот> <имя>: кадр[:значение], …`
  (пока в `spacekit.shot` нет общего хелпера — печатать в шоте вручную; куда их класть — `--events-to pulses|risers|none`).
- Логи: превью — `out/<ep>/9x16/logs/prev_<шот>.log`, финал — `out/logs/<ep>/render_<шот>.log` (cues.py берёт финальный,
  если его нет — превью). Вспышки считаются при сборке сцены, поэтому **cue готовить по логам превью, до финала**.
- Перевод в секунды монтажа: `t = (offset + f − first) / fps`, где `offset` — начало шота в монтаже
  (Σ `frames` предыдущих `edit` − Σ `xfade_in` до текущего включительно), `first` — `edit[].first` (по умолчанию 1).
  Кадры вне `[first, first + frames − 1]` отбрасываются.
- Порог ≈ 0.4 (в ep001 0.44 вошёл, 0.32 и 0.20 — нет). Вспышки, когда пульсар перекрыт (за планетой), исключать
  руками (`--exclude v5:1-201`). Вспышка на последнем кадре шота = склейка — оставлять.
- `risers` — моменты склеек (≥ 2 с от начала).
- Всё это делает `python tools/cues.py episodes/<ep>/episode.json [--thr 0.4] [--exclude vN:a-b] [--min-riser 2.0] [--events-to pulses|risers|none] [--logs DIR] [--dry-run]`:
  пишет `pulses`/`risers` в `music_cues.json`, не трогая гармонию. Полный CLI — в его docstring.
  (В ep001 удары ставились как `(offset + f)/fps` — на 1 кадр позже.)

## Титры и субтитры (`episode.json`)

**Координаты:** `x`, `y` — доли кадра; **`y` отсчитывается от НИЗА** (0 — низ, 1 — верх), `x` — от левого края;
якорь — центр текста. `size` — px при 1080×1920.

**Безопасные зоны Shorts** (интерфейс перекрывает низ, правый край и верх): важный текст — `y ≥ 0.22`,
`x` в пределах 0.08–0.85, верх ≤ 0.93. Для центрированного текста с `wrap` w: `x − w/2 ≥ 0.08` и `x + w/2 ≤ 0.85`
(например, `x 0.465, wrap 0.76`). В ep001 `x 0.5, wrap 0.84` — правый край до 0.92, в новых эпизодах так не делать.
Плашка «Real numbers · cinematic visualization» на `y 0.955` — некритичная, может перекрываться.

`caption_style` (субтитры; умолчания `editkit/assemble.py`):

| Поле | По умолчанию | Что |
|---|---|---|
| `size` | 72 | кегль, px |
| `x`, `y` | 0.5, 0.36 | центр строки, доли кадра (y от низа) |
| `font` | шрифт Blender | путь к .ttf; **если файла нет — молча шрифт по умолчанию** (проверяет `check_episode.py`) |
| `color` | [1, 1, 1] | линейный RGB |
| `outline` | 6 | толщина обводки: > 1 — проценты (6 → 0.06), ≤ 1 — доля (разрыв шкалы: 1 ≠ 2) |
| `shadow` | true | мягкая тень |
| `wrap` | 0.86 | ширина переноса, доля ширины кадра |

`overlays.en[]` (титры): `text`, `start_s` (0), `length_s` (весь ролик), `size` (56), `x` (0.5), `y` (0.5),
`font`, `color` ([0.92, 0.94, 1.0]), `fade` (20 кадров; 0 — без затухания; `length` ≥ 2·`fade`), `align` (`CENTER`),
`outline` (0), `shadow` (true), `wrap` (нет). Поля `highlight` нет (в docstring assemble — не реализовано).

**Текст субтитров** (`script_9x16.json`): фраза бьётся на куски ≤ 26 символов (`caption_max_chars` в сценарии или `tools/tts.py --max-chars N`):
по знакам препинания, затем сбалансированно; служебное слово не висит в конце, число не отрывается от единицы.
- `en_cap` — текст субтитров, если он отличается от произносимого: цифры вместо слов («161», «20 km», «1992»),
  смысл тот же. Произносимый текст — словами (TTS читает числа плохо).
- `|` в `en_cap` (или в самом тексте) — ручные разрывы: куски ровно как размечено, авторазбивка отключается.
- **Тайминг:** Kokoro не даёт границ слов: время кусков делится пропорционально числу символов (то же для
  `en_cap`, отличного от произносимого, на любом движке). Рассинхрон до
  0.3–0.5 с на длинных фразах — ожидаем; проверять глазами (QA-кадр в середине каждой длинной фразы).

## QA

**Кадры — до сборки** (секунды, без Blender; в финале очередь запускает сама после последней порции):

```bash
python tools/framecheck.py episodes/<ep>/episode.json      # [--shots v1,v2] [--frames DIR]; код 0 PASS, 1 FAIL
```

- Целость: каждый кадр `edit` (`first`…`first+frames−1`) есть, не пустой, PNG с IHDR = `format.w×h` и IEND в конце.
- Разовый сбой рендера: кадры без ошибок в логе, но с другим светом/шумом (ep002: rinat-pc, v1 135–165, антенна
  без солнца). Видно по размеру PNG: шаг между соседними кадрами |Δ| > 2 % и > 6× медианы |Δ| в окне ±10 кадров
  (фон обычно 0,05–0,7 %). Пара скачков разного знака — блок «вход/выход»: `СБОЙ 135–165: вход 135 −4,7 %,
  выход 166 +5,2 %`; скачок без пары — сбой с края шота (какой край — по кадрам глазами).
- Задуманные события — не ошибка: скачок в ±3 кадрах от `EVENT` или ±15 от `FLASH` шота (логи — как у `cues.py`)
  печатается как `событие` (ep002: v2 26–28 у EVENT sunrise 27; ep001: подъём/спад луча пульсара — до 12 кадров
  от пика FLASH). Задуманный скачок без строки EVENT даст FAIL — сравнить кадры глазами, чисто — собирать, а в шоте
  печатать EVENT на таких моментах.
- FAIL → кадры из строк `RERENDER` удалить в снимке `<snapshot>/out/<ep>/9x16/frames/<шот>/` (`snapshot` — из
  `render_queue.py status --json`; рендер на rinat-pc — и в `D:\orbitfall\out\<ep>\9x16\frames\<шот>\`), затем
  `render_queue.py retry JOB --rerender-shots vN`: очередь докачает кадры и повторит framecheck.

**Готовый MP4.** `editkit/verify_video.py` **сам ничего не проверяет**: печатает размер/fps/кадры/секунды/байты и выгружает указанные
кадры в PNG. Вердикт — `tools/qa.py`:

```bash
python tools/qa.py episodes/<ep>/episode.json en
```

Считает кадры QA по `edit` (2, каждая склейка ±1, середины шотов, последний), вызывает verify_video,
проверяет 1080×1920 / 60 fps / кадры == Σ edit.frames − Σ xfade_in / ≤ 30,0 с и печатает PASS или FAIL. Глазами по PNG: субтитры в
безопасных зонах, читаемость, петля (последний кадр ≈ первый), нет чёрных/битых кадров. Ручной вызов verify_video:
`"/d/Blender/blender.exe" -b --factory-startup -P editkit/verify_video.py -- out/<ep>/9x16/<ep>_en_1080x1920p60.mp4 out/<ep>/9x16/qa_en <кадры из строки FRAMES: python tools/qa.py episodes/<ep>/episode.json en --dry-run>`.

## Правила конвейера (против «inauthentic content»)

Политика оценивает канал целиком: «content feels interchangeable from video to video» — не монетизируется
(research.md:63); CGI с малой вариативностью прямо отнесён к шаблонному (уточнение 16.07.2026, research.md:124);
одинаковая музыка + однотипная картинка + ИИ-скрипт одним голосом — пример массового производства (research.md:148).

- Новый объект → новые шоты и драматургия; библиотека — кирпичи, не шаблон. Минимум 1 новый визуальный приём
  на ролик (новый модуль, ракурс, эффект).
- Музыка — новая гармония/темп/тембр на каждый ролик (`music_cues.json`, значения не копировать), «честный звук» объекта где возможно.
- **Голос канала — Kokoro `af_heart` ×0.98** (решение владельца 18.10.2026, эп. 002: узнаваемый диктор во всех
  роликах). Однотипность снимать подачей и темпом фраз, структурой и раскладкой субтитров (y, кегль, шрифт, цвет —
  по сериям); собственный (клонированный) голос — позже.
- Темы — по всему космосу, не серией однотипных пульсаров: соседние ролики — разные классы объектов.
- Каждое число — с источником в описании.

**Чек-лист вариативности** (в сообщение на одобрение, `docs/approval.md`) — что отличается от прошлых эпизодов
(`episodes/INDEX.md`): камера (ракурсы, ход, объективы) · структура (порядок блоков, число шотов, где кульминация) ·
хук (тип: число / вопрос / визуальный шок) · музыка (тональность, лад, темп, тембр) · голос (диктор, темп) ·
субтитры (раскладка, стиль).
