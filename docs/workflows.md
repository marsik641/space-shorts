# Роли воркфлоу конвейера

На них ссылаются `/make-video` (факты, бриф, критика) и `/next-video` (быстрый фактчек). Запуск:
- **Workflow-скрипт** (Claude, skill `workflow-authoring`) — запускать без отдельного вопроса, если агент считает его
  эффективнее субагентов (много независимых проверок, состязательный фактчек, 3–5 критиков). Это постоянное
  согласие владельца (22.10.2026); прямой запрет в текущем чате («сейчас не надо») важнее;
- **иначе субагенты** (Claude — Agent; Codex — свои субагенты) с промптами ниже, параллельно где можно;
- **fallback** — последовательный самопрогон по чек-листу роли тем же форматом вывода.

Общие правила для всех ролей: по-русски, кратко; только реальные источники (URL), без выдуманных ссылок;
Blender, TTS, музыку не запускать (только чтение файлов и сеть). Роли читают файлы worktree ролика, отчёт —
файлом в `episodes/<ep>/` (коммитится вместе с правками раунда); в `/next-video`, до папки эпизода, — блоком
«Фактчек» в ideas-файле. Планка картинки — `docs/quality.md`.

---

## 1. Исследователь (факты)

**Вход:** объект и крючок из `ideas/<дата>_options.md` (выбранный вариант + правки), `docs/channel.md` (серия).
**Промпт:**
> Собери факты для 30-секундного Shorts про <объект>. Нужны 8–15 фактов, пригодных для озвучки, — каждый с
> числом/формулировкой и первоисточником: каталог (ATNF Pulsar Catalogue, NASA Exoplanet Archive, SIMBAD,
> JPL SSD/Horizons), рецензируемая статья (arXiv/DOI), страница миссии или пресс-релиз NASA/ESA/ESO/IAU. Для каждого — уверенность (высокая: прямое
> измерение; средняя: модель/оценка; гипотеза). Отдельно: самые зрелищные факты (что можно показать эффектно) и
> визуальные материалы — снимки телескопов, художественные реконструкции NASA/ESA/ESO (URL) как референсы вида.
> Не используй Википедию как источник (только как навигацию).

**Выход:** `episodes/<ep>/facts.md` — таблица `| Факт в ролике | Значение | Источник (URL) | Уверенность |` + блок
«Визуальные референсы» + блок «Гипотезы (в тексте — likely/might)».

## 2. Фактчекер

**Вход:** `facts.md`, `script_9x16.json`, оверлеи `episode.json`, `publish_en.md` (если уже есть).
**Промпт:**
> Проверь каждое число и утверждение в facts.md, в сценарии, титрах и publish_en.md по указанному источнику: открой
> URL, найди значение. Сверь округления в тексте ролика («twenty kilometers» при диаметре 20–26 км — пометить).
> Для гипотез проверь, что в тексте стоит likely/probably/might. Картинку не оценивай: визуальные условности
> разрешены (`docs/quality.md`). Ничего не правь сам — только вердикты.

**Выход:** таблица `| Утверждение | Вердикт OK / исправить / убрать | Как должно быть | URL |` + список расхождений
сценария с facts.md. Всё «исправить/убрать» — применить до сценария/превью; после «ок» пользователя —
остановка по `docs/approval.md`.

## 3. Постановщик (визуальный бриф)

**Вход:** `facts.md` (блок «Визуальные референсы»), сценарий-черновик, `docs/quality.md`, `episodes/INDEX.md`.
**Промпт:**
> Ты — режиссёр-постановщик космического Shorts уровня трейлера, а не научно-популярной инфографики. По
> `docs/quality.md` и шаблону `episodes/_template/visual_brief.md` заполни бриф: 5–8 референсов (URL), палитру,
> свет, камеру и событие каждого шота, money shot, первый кадр, условности. Для каждого шота — чем он будет
> красивее, чем генерация Veo/NanoBanana на эту тему. Повторы приёмов из `episodes/INDEX.md` пометь.

**Выход:** `episodes/<ep>/visual_brief.md`. Бриф смотрит критик «Кино» до написания шотов.

## 4. Критики (3–5 параллельно)

**Вход:** бриф (раунд 0), затем hero-кадры F — `out/<ep>/9x16/hero/` и `sheet_hero.png` (100 %, сэмплы финала,
`docs/quality.md`, «Ворота»), лист превью `sheet_prev.png`, черновое видео (если есть), `script_9x16.json`,
`episode.json`, docstring `shots_9x16.py`, `visual_brief.md`, `episodes/INDEX.md`, отчёт TTS.
Роли (каждая — свой субагент):

| Критик | Смотрит | Вето |
|---|---|---|
| **Кино/вау** (обязателен) | Остановит ли кадр скролл рядом с генерацией Veo/NanoBanana и референсами брифа: глубина (≥ 3 плана), свет (ключ + контр, ореолы, объём), палитра, детализация на всех масштабах, движение камеры, оптика (блум, DOF, моушн-блюр), событие в шоте, первый кадр, money shot. Оценка **1–10 каждому шоту** | шот < 8 |
| **Композиция/вертикаль** | 9:16: объект в центре внимания, нет пустых кадров; субтитры и титры в безопасных зонах Shorts (y ≥ 0.22, x 0.08–0.85, верх ≤ 0.93 — `docs/pipeline.md`, «Титры и субтитры») | текст вне зон |
| **Ритм/хук** | Хук и движение в первые 1–2 с, смена плана каждые 2–5 с, склейки на событиях (FLASH/EVENT) и ударах музыки, петля конец→начало | нет хука |
| **Факты** | Только четыре блокера `docs/quality.md`: ложное число в словах/титрах, чужой объект под видом этого, гипотеза как факт, картинка против произносимого факта. Всё остальное о «физичности» — minor-подсказка | 4 пункта |
| **Уникальность** (опц.) | Сравнение с `episodes/INDEX.md`: что повторяет прошлые эпизоды (ракурсы, структура, хук, музыка, раскладка субтитров) | — |
| **Звук/текст** (опц.) | OVERRUN, читаемость субтитров (≤ 26 символов, `en_cap` с цифрами), рассинхрон Kokoro | OVERRUN |

**Промпт (общий каркас):**
> Ты — критик роли «<роль>». Посмотри файлы <список>. Найди проблемы только своей роли. Для каждой: шот,
> кадр, проблема, конкретная правка (параметр/значение или что переснять), severity (blocker / major / minor).
> Не больше 10 пунктов, без похвалы. Если проблем нет — «нет замечаний».

Для «Кино/вау» добавить:
> Ты — арт-директор, который отбирает ролики для канала с миллионами просмотров. Будь строг: «аккуратно и
> правдоподобно» — это 5, «красиво» — 7, «остановлюсь и пересмотрю» — 9. Для каждого шота: оценка, что тянет
> вниз, 1–3 правки, которые поднимут оценку сильнее всего (свет, палитра, глубина, камера, эффект, сэмплы).
> Факты и физику не оценивай.

**Выход:** `| Шот | Кадр | Проблема | Правка | Severity |` (у «Кино» — плюс столбец оценки).

**Лимит:** «Кино/вау» — до **3 раундов**, остальные роли — до **2**. Blocker после последнего раунда правится
обязательно; если «Кино» всё ещё < 8 — честно сказать владельцу в сообщении на одобрение (оценки по шотам и что
мешает). Остальные открытые замечания — туда же (`docs/approval.md`, «Открытые замечания»).
