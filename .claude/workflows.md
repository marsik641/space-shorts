# Роли воркфлоу конвейера

На них ссылаются `/make-video` (факты, критика превью) и `/next-video` (быстрый фактчек). Запуск:
- **Workflow-скрипт** — только если пользователь на него согласился (skill `workflow-authoring`);
- **иначе субагенты** (Agent/Task) с промптами ниже, параллельно где можно;
- **fallback** — последовательный самопрогон по чек-листу роли тем же форматом вывода.

Общие правила для всех ролей: по-русски, кратко; только реальные источники (URL), без выдуманных ссылок;
Blender, TTS, музыку не запускать (только чтение файлов и сеть); при `out/RENDER.lock` — тем более.

---

## 1. Исследователь (факты)

**Вход:** объект и крючок из `ideas/<дата>_options.md` (выбранный вариант + правки), `docs/channel.md` (серия).
**Промпт:**
> Собери факты для 60-секундного Shorts про <объект>. Нужны 8–15 фактов, пригодных для озвучки, — каждый с
> числом/формулировкой и первоисточником: каталог (ATNF Pulsar Catalogue, NASA Exoplanet Archive, SIMBAD,
> JPL SSD/Horizons), рецензируемая статья (arXiv/DOI), страница миссии или пресс-релиз NASA/ESA/ESO/IAU. Для каждого — уверенность (высокая: прямое
> измерение; средняя: модель/оценка; гипотеза). Отдельно: условности визуализации (что будет не в масштабе,
> замедлено, показано видимым). Не используй Википедию как источник (только как навигацию).

**Выход:** `episodes/<ep>/facts.md` — таблица `| Факт в ролике | Значение | Источник (URL) | Уверенность |` + блок
«Условности» + блок «Гипотезы (в тексте — likely/might)».

## 2. Фактчекер

**Вход:** `facts.md`, `script_9x16.json`, `publish_en.md` (если уже есть).
**Промпт:**
> Проверь каждое число и утверждение в facts.md (и в сценарии, и в publish_en.md) по указанному источнику: открой URL,
> найди значение. Сверь округления в тексте ролика («twenty kilometers» при диаметре 20–26 км — пометить).
> Для гипотез проверь, что в тексте стоит likely/probably/might. Ничего не правь сам — только вердикты.

**Выход:** таблица `| Утверждение | Вердикт OK / исправить / убрать | Как должно быть | URL |` + список расхождений
сценария с facts.md. Всё «исправить/убрать» — применить до сценария/превью; после «ок» пользователя —
остановка по `docs/approval.md`.

## 3. Критики превью (3–5 параллельно)

**Вход:** контактный лист(ы) `out/<ep>/9x16/sheet_prev<k>.png`, превью `out/<ep>/9x16/previews/*.png`,
`script_9x16.json`, `episode.json`, docstring `shots_9x16.py`, `episodes/INDEX.md`, отчёт TTS.
Роли (каждая — свой субагент):

| Критик | Смотрит |
|---|---|
| **Композиция/вертикаль** | 9:16: объект в центре внимания, нет пустых кадров; центр заголовков и субтитров совпадает с центром кадра (`x=0.5`, `wrap≤0.70`); безопасные зоны Shorts: y ≥ 0.22, края текста x 0.08–0.85, верх ≤ 0.93 — `docs/pipeline.md`; первый кадр — сильный |
| **Физика/факты** | Свет только от реальных источников, масштабы/цвета/скорости согласованы с facts.md и условностями; лучи, орбиты, фазы освещения правдоподобны |
| **Ритм/хук** | Хук в первые 1–2 с, смена плана каждые 4–10 с, склейки на событиях (FLASH/EVENT), петля конец→начало, фраза не перекрывает склейку неудачно |
| **Уникальность** (опц.) | Сравнение с `episodes/INDEX.md`: что повторяет прошлые эпизоды (ракурсы, структура, хук, музыка, голос, раскладка субтитров) |
| **Звук/текст** (опц.) | OVERRUN, читаемость субтитров (≤ 26 символов, `en_cap` с цифрами), рассинхрон Kokoro |

**Промпт (общий каркас):**
> Ты — критик превью роли «<роль>». Посмотри файлы <список>. Найди проблемы только своей роли. Для каждой: шот,
> кадр, проблема, конкретная правка (параметр/значение или что переснять), severity (blocker / major / minor).
> Не больше 10 пунктов, без похвалы. Если проблем нет — «нет замечаний».

**Выход:** `| Шот | Кадр | Проблема | Правка | Severity |`.

**Лимит:** не больше **2 раундов** «критика → правки → повтор превью». Blocker после 2-го раунда — правится
обязательно; остальные открытые замечания — в сообщение на одобрение (`docs/approval.md`, «Открытые замечания»).
