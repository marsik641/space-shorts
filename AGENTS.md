# space-shotrs — как работать в этом репозитории

Единые правила для всех агентов (Claude Code читает их через `@AGENTS.md` в `CLAUDE.md`, Codex — напрямую).
Правило меняешь — меняй здесь; в `CLAUDE.md` — только специфика Claude.

Конвейер Shorts канала **The Universe Inside Out** (`@TheUniverseInsideOut`, «Real objects. Real numbers. Turned
inside out.»): реальные объекты + реальные числа → кинематографичный рендер Blender Cycles → вертикальный ролик с
озвучкой → пакет к загрузке. Канал — про весь космос (планеты, луны, звёзды, чёрные дыры, галактики, экзопланеты,
кометы, миссии, масштаб, «что если»). Обзор — `README.md`, процесс — `docs/pipeline.md`, канал — `docs/channel.md`.

## Главные правила

- **Картинка — приоритет №1** (`docs/quality.md`). Ролик должен выглядеть как кино и останавливать скролл —
  не хуже генераций Veo/NanoBanana. **Факты — в словах, зрелище — в картинке:** художественные условности
  (масштаб, цвет, свет, видимое невидимое, сжатое время) — норма и идут списком в описание; блокируют только
  ложные числа и утверждения. Не жертвовать зрелищем ради буквальной физичности кадра.
- **Каждый ролик уникален.** YouTube с 15.07.2025 демонетизирует «inauthentic content» (шаблонный массовый
  контент). Новый объект = свои шоты, своя драматургия, свой хук, своя гармония музыки. Библиотека даёт
  кирпичи, а не шаблон ролика. Нельзя клонировать episodes/ep001 с заменой имени объекта.
- **Только EN.** `episode.json` → `languages: ["en"]`, в сценарии — только `en`/`en_cap`; RU-озвучки, монтажа,
  QA и публикации нет. Монетизация — решение отложено (`docs/publish.md`).
- **Слова проверяются.** Каждое число в озвучке, титрах и описании — с источником (каталог: ATNF, NASA Exoplanet
  Archive, JPL; статья; страница миссии). Источники — в `publish_en.md` и закреплённом комментарии. Гипотезы —
  с «likely/probably».
- **Пользователь одобряет до рендера** (`docs/approval.md`): сценарий, hero-кадры, черновое видео. После «ок»
  `/make-video` идёт до конца — до пакета `out/<ep>/release/` (**два файла**: мастер MP4 и `publish_en.md`,
  `docs/publish.md`), их же — пользователю, и до влитой в main ветки ролика.
- **Своя музыка** (`tools/music.py`) — никаких сторонних треков: любая претензия по авторскому праву бьёт по
  ролику и каналу.
- **Длительность: цель 29–29,5 с, жёсткий максимум 30,0 с** (`docs/shorts_format.md`). При 60 fps монтаж ≤ **1799
  кадров**: VSE пишет звук на всю длину сцены, а AAC округляет вверх до блоков 1024 сэмпла (1800 кадров → дорожка
  30,016 с, `qa.py` = FAIL).
- **Рендер-бюджет финала — до 6 ч GPU**, планировать 4–6 ч: запас идёт в качество (`docs/quality.md`).

## Конвейер чатов: один ролик = один чат = одна worktree

| Шаг | Кто | Что |
|---|---|---|
| 1 | пользователь | `/next-video` в новом чате, открытом в основной копии |
| 2 | агент | `python tools/video_wt.py start` → worktree `../space-shotrs.wt/epNNN`, ветка `video/epNNN`, номер зарезервирован; дальше всё — там. 3 варианта → коммит → стоп |
| 3 | пользователь | `/make-video N` (или «делаем N» + правки) в том же чате |
| 4 | агент | `video_wt.py claim <slug>` → часть A: факты, бриф, сценарий, шоты, hero-кадры, критика, черновое видео → **стоп на одобрение** |
| 5 | пользователь | «ок» или правки |
| 6 | агент | часть B: финал через очередь → визуальный QA → `release/` пользователю → учёт → `video_wt.py finish` (ветка влита в main) → `remove` |

**DoD ролика** — все пункты сразу: release (2 файла) готов и передан; визуальный QA принят (`render_queue.py
accept`); всё закоммичено; `video_wt.py finish` влил ветку в main; worktree убрана. До этого ролик не готов и
«ПК свободен» другим чатам не сообщается. Подробно — `docs/pipeline.md`, «Чаты и worktree».

## Работа агентов (Claude и Codex, в том числе одновременно)

- **Основная копия общая.** В ней одновременно живут очередь рендера и чужие чаты, поэтому файлы в ней не правят и
  не коммитят. В ней — только чтение, `tools/video_wt.py start/status/remove` и `tools/render_queue.py`. Любая
  правка — в своей worktree: ролик — `video_wt.py start`, другая задача — `video_wt.py start --task <slug>`.
  Чат уже открыт приложением в worktree — `start --here`. В main работа попадает только через `video_wt.py finish`
  (`git merge --ff-only`). Claude: после `start` — `EnterWorktree` с выданным `path`; Codex: `workdir` = этот путь.
- **Чужое не трогать.** Чужие worktree, ветки, задания очереди и снимки `out/q/<JOB>` — только читать. Чужие
  незакоммиченные правки не коммитить, не откатывать, не форматировать. Без `git stash` (стек общий на все
  worktree), `reset --hard`, `checkout -- .`, `clean`, `push --force`, переписывания влитой истории;
  `git status` по чужой копии — с `--no-optional-locks` (иначе пишет её `index.lock`).
- **Общие ресурсы — только через инструменты:** номер эпизода — `video_wt.py` (резерв `refs/video/epNNN`), GPU,
  TTS, музыка и сборка — очередь (`docs/render_queue.md`), main — `finish`.
- **Коммиты — по логическим блокам**, сразу как блок готов (варианты; эпизод и факты; бриф; сценарий; модуль
  spacekit; шоты; правки раунда критики; одобрение; учёт и уроки). Формат — Conventional Commits:
  `type(scope): описание по-русски`; type — `feat`, `fix`, `refactor`, `perf`, `docs`, `test`, `chore`; scope —
  эпизод (`ep010_kepler16b`), модуль или область (`spacekit`, `render-queue`, `pipeline`, `harness`). Тело — зачем.
  Последняя строка — трейлер модели, которая сделала работу, с её точным именем:
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` или `Co-Authored-By: Codex (GPT-5.4) <noreply@openai.com>`.
  Чужую работу коммитить с трейлером её автора. Служебный merge от `finish` — без трейлера.
- **Грязное дерево = работа не закончена.** Ход, в котором агент говорит «готово», кончается чистой worktree;
  задача — влитой в main веткой. Не своё и не готовое — назвать в ответе, а не оставлять молча.
- **Конфликты** при `finish` решаются в своей worktree с сохранением чужих правок; спорный конфликт — вопрос
  владельцу. Харнесс-правки, найденные по ходу ролика (доки, tools), — отдельным коммитом в ветке ролика или
  отдельной задачей `start --task`.

## Окружение

- Blender 5.2.2: `"/d/Blender/blender.exe"` (Git Bash). Скрипты: `blender -b --factory-startup -P <script> -- <args>`.
- Рендер-ПК два: этот и rinat-pc (ssh через Tailscale). **Любые Blender/тяжёлый звук — через общую очередь**
  `tools/render_queue.py`, команды — `docs/render_queue.md`. Чаты независимо отправляют `submit preview` или
  после одобрения `submit final --approved 'контекст одобрения'`; очередь сама выбирает ПК и продолжает до
  пакета к загрузке и `needs_review` (нужен просмотр глазами). Снимки кода изолированы; очередь общая для всех
  git worktree (`out/q` основной копии). В старой worktree без клиента очереди вызывай скрипт из основной,
  передавая свой episode.json. Внутри Blender: Python 3.13 + numpy (scipy нет).
- Оболочка: команды в доках — для Git Bash. В PowerShell: Blender — `& 'D:\Blender\blender.exe'`, venv —
  `.venv\Scripts\python.exe` основной копии (в worktree `.venv` нет; путь печатает `video_wt.py start`).
- `.venv` (Python 3.14): kokoro-onnx (работает на 3.14 через onnxruntime, в отличие от пакета kokoro), edge-tts,
  soundfile, scipy, pyloudnorm — для звука. Озвучка — Kokoro (Apache-2.0, офлайн); edge-tts — серая зона
  ToS Microsoft при коммерческом использовании, без нужды не брать. Веса Kokoro — `assets/tts/` основной копии.
- GPU: RTX 3060 8 ГБ, OptiX. Замеры с/кадр и формула ETA — `docs/timings.md`.
- ffmpeg в системе нет: кодирование и чтение видео — через Blender (`editkit/`).

## Грабли (проверено)

- **Пути.** Процессы из MSIX-приложений (Claude, Codex) видят `AppData\Roaming\<приложение>\…` через
  MSIX-редирект (+50 символов); Blender падает на путях > 260 символов. Выводы — только в `out/` своей копии,
  имена короткие; worktree — в `space-shotrs.wt/<короткое имя>`.
- **Кириллица в пути** (`Проекты`): espeak-ng (фонемизатор Kokoro) её не читает — `tools/tts.py` копирует
  данные в `%LOCALAPPDATA%/space-shorts`. Аналогичные C-библиотеки могут вести себя так же.
- **Один Blender на ПК.** Во время финала CPU не грузить: Cycles на GPU, но синхронизация сцены и компоузер — на
  CPU (кадр замедляется вдвое, на 8 ГБ возможен OOM). **Прямые запуски запрещены**: превью, замеры, контактные
  листы, финал, сборка и тяжёлый звук — через очередь. Она атомарно проверяет общий lock и процессы перед каждым
  шагом. При занятом GPU продолжать текстовую работу и ставить задания; не ждать в чате. Замеры рядом с чужим
  рендером завышены вдвое и тормозят его — очередь их сериализует.
- **Остановка рендера** — `render_queue.py cancel JOB` (своё дерево процессов) или `pause JOB` (после текущей
  порции); верхний bash/Python не убивать. Процесс Blender вне очереди (старый ручной запуск) добивать по
  командной строке (PowerShell: `Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -like '*<скрипт>*' }`
  → `Stop-Process`), только свой — по эпизоду в командной строке. `out/RENDER.lock` очереди и чужие lock не снимать.
- Blender 5.x API: компоузер — `scene.compositing_node_group` + `NodeGroupOutput`; параметры Glare — входные
  сокеты; видео — `image_settings.media_type="VIDEO"`; VSE — `sequence_editor.strips`; у action — слоты/каналбэги
  (`spacekit.anim.fcurves`). Анимация — только ключами: Python-драйверы в фоне без autoexec не работают.
- fps берётся из сцены (`core.scene_fps`); не хардкодить.
- Время рендера: компоузер на GPU (`render.setup_cycles` ставит сам), `use_persistent_data` в секвенциях.
- Детерминизм: сиды фиксированные; не использовать `hash(str)` (рандомизирован между запусками).
- Регресс библиотеки: `tools/imgdiff.py` — рендер старого кадра новой версией и сравнение (эпизод 001 16:9 —
  эталон, кадры в `out/ep001_psr_b1257/16x9/frames`, но у s1 сохранились только кадры 1–31).

## Соглашения

- Код и комментарии — по-русски, кратко, в стиле `spacekit/`. Скрипты идемпотентны, сцены строятся с нуля.
- Эпизод: `episodes/epNNN_<slug>/` — `facts.md`, `visual_brief.md`, `system.py`, `shots_9x16.py`,
  `script_9x16.json`, `music_cues.json`, `episode.json`, `edit_9x16_en.json` (генерирует `build_edit.py`; коммитить —
  воспроизводимость монтажа), `publish_en.md`. Выход — `out/epNNN_<slug>/9x16/`, пакет — `out/epNNN_<slug>/release/`.
- Номер и slug выдаёт `tools/video_wt.py` (`start` — номер, `claim` — slug): slug — `[a-z0-9_]`, ≤ 16 символов, по
  каталожному имени (`psr_j1748`, `trappist1`, `sgr_a`): лимит путей 260. Номер не переиспользуется.
- Перед превью и перед финалом — `tools/check_episode.py <episode.json>`. После рендера, до сборки —
  `tools/framecheck.py` (очередь запускает сама). После сборки — `tools/qa.py <episode.json> en`, релиз —
  `tools/release.py` (тоже в очереди финала).
- Скиллы: `.claude/skills/<имя>/SKILL.md` и `.agents/skills/<имя>/SKILL.md` — одинаковые копии (Claude и Codex);
  правишь одну — копируй во вторую, `tests/test_harness.py` это проверяет. Роли воркфлоу — `docs/workflows.md`.
- Тесты: `python -m unittest discover -s tests` (без GPU и сети; `finish` гоняет их сам).
