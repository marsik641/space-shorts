# space-shotrs — как работать в этом репозитории

Конвейер Shorts канала **The Universe Inside Out** (`@TheUniverseInsideOut`, «Real objects. Real numbers. Turned inside out.»): реальные объекты +
реальные параметры → рендер Blender Cycles → вертикальный ролик с озвучкой → пакет к загрузке. Канал — про весь космос
(планеты, луны, звёзды, чёрные дыры, галактики, экзопланеты, кометы, миссии, масштаб, «что если»); нейтронные звёзды
эп. 001 — только начало. Обзор и структура — `README.md`, процесс — `docs/pipeline.md`, канал — `docs/channel.md`.

## Главные правила

- **Каждый ролик уникален.** YouTube с 15.07.2025 демонетизирует «inauthentic content» (шаблонный массовый
  контент). Новый объект = свои шоты, своя драматургия, свой хук, своя гармония музыки. Библиотека даёт
  кирпичи, а не шаблон ролика. Нельзя клонировать episodes/ep001 с заменой имени объекта.
- **Только EN.** Ролики выпускаются только на английском: `episode.json` → `languages: ["en"]`, в сценарии — только
  `en`/`en_cap`, никаких RU-озвучки, монтажа, QA и публикации. Инструменты технически поддерживают другие языки —
  RU можно вернуть позже, сейчас на него время не тратим. Монетизация — решение отложено (`docs/publish.md`).
- **Факты проверяются.** Каждое число в сценарии — с источником (каталог: ATNF, NASA Exoplanet Archive, JPL; статья;
  страница миссии). Источники идут в `publish_en.md` и закреплённый комментарий. Спекуляции — с «likely/probably».
- **Пользователь одобряет до рендера.** Рендер — часы GPU. Шаги «выбор темы» и «одобрение сценария+превью» —
  обязательные точки согласования (см. `docs/pipeline.md`). Состав сообщения на одобрение и что можно менять после
  «ок» без вопроса (а что требует остановки) — `docs/approval.md`. После «ок» `/make-video` идёт до конца: итог —
  пакет к загрузке `out/<ep>/release/` — **два файла**: мастер MP4 и `publish_en.md` (`docs/publish.md`); их же —
  пользователю. Отдельной команды publish-pack нет.
- **Своя музыка** (`tools/music.py`) — никаких сторонних треков: Shorts > 60 с с любой претензией по авторскому
  праву (Content ID или ручной) блокируется глобально.
- Длительность Shorts: **цель 59–59,5 с, жёсткий максимум 60,0 с**. При 60 fps монтаж ≤ **3599 кадров**: VSE пишет звук
  на всю длину сцены, а AAC округляет вверх до блоков 1024 сэмпла (3600 кадров → дорожка 60,011 с, `qa.py` = FAIL).

## Окружение

- Blender 5.2.2: `"/d/Blender/blender.exe"` (Git Bash). Скрипты: `blender -b --factory-startup -P <script> -- <args>`.
- Рендер-ПК два: этот и rinat-pc (по ssh через Tailscale, `tools/remote_render.py`, `docs/remote_render.md`). Ролики
  рендерятся параллельно из разных чатов; свободный ПК перед стартом рендера выбирается по `docs/remote_render.md`
  («Два ПК: какой свободен»), без вопроса пользователю.
  Внутри Blender: Python 3.13 + numpy (scipy нет).
- Оболочка: команды в доках — для Git Bash (Bash tool; `render_episode.sh` нужны bash и cygpath). В PowerShell:
  Blender — `& 'D:\Blender\blender.exe'`, venv — `.venv\Scripts\python.exe`.
- `.venv` (Python 3.14): kokoro-onnx (работает на 3.14 через onnxruntime, в отличие от пакета kokoro), edge-tts,
  soundfile, scipy, pyloudnorm — для звука. Озвучка — Kokoro (Apache-2.0, офлайн); edge-tts — серая зона
  ToS Microsoft при коммерческом использовании, без нужды не брать. Веса Kokoro — `assets/tts/`.
- GPU: RTX 3060 8 ГБ, OptiX. Замеры с/кадр и формула ETA — `docs/timings.md` (ep001: крупный план пульсара
  3,8–4,4 с/кадр).
- ffmpeg в системе нет: кодирование и чтение видео — через Blender (`editkit/`).

## Грабли (проверено)

- **Пути.** Процессы из Claude-приложения видят `AppData\Roaming\Claude\…` через MSIX-редирект (+50 символов);
  Blender падает на путях > 260 символов. Выводы — только в `out/` этого репо, имена короткие.
- **Кириллица в пути** (`Проекты`): espeak-ng (фонемизатор Kokoro) её не читает — `tools/tts.py` копирует
  данные в `%LOCALAPPDATA%/space-shorts`. Аналогичные C-библиотеки могут вести себя так же.
- **Один Blender за раз.** Во время финального рендера не грузить CPU (превью, TTS, музыка, pip): Cycles на GPU, но
  синхронизация сцены и компоузер — на CPU; кадр замедлялся 6 → 12 с, на 8 ГБ возможен OOM.
  **Есть `out/RENDER.lock` или `tasklist` показывает `blender.exe` — только текстовая работа** (факты, сценарий,
  `system.py`, код шотов); превью/TTS/музыку — в очередь, пользователю — ETA текущего рендера.
  Проверять **перед каждым** запуском Blender, включая замеры с/кадр и тестовые превью (ep003: замеры рядом с чужим
  рендером дали вдвое завышенные цифры и тормозили его).
- **Остановка фонового цикла рендера** (TaskStop) убивает только верхний bash: дочерний цикл и `blender.exe`
  живут дальше и запускают следующие шоты. Добивать по командной строке (PowerShell: `Get-CimInstance
  Win32_Process | Where-Object { $_.CommandLine -like '*<скрипт>*' }` → `Stop-Process`), затем снять свой
  `out/RENDER.lock`. Свои процессы отличать от чужих по эпизоду в командной строке.
- Blender 5.x API: компоузер — `scene.compositing_node_group` + `NodeGroupOutput`; параметры Glare — входные
  сокеты; видео — `image_settings.media_type="VIDEO"`; VSE — `sequence_editor.strips`; у action — слоты/каналбэги
  (`spacekit.anim.fcurves`). Анимация — только ключами: Python-драйверы в фоне без autoexec не работают.
- fps берётся из сцены (`core.scene_fps`); не хардкодить 30.
- Время рендера: компоузер на GPU (`render.setup_cycles` ставит сам), `use_persistent_data` в секвенциях.
- Детерминизм: сиды фиксированные; не использовать `hash(str)` (рандомизирован между запусками).
- Регресс библиотеки: `tools/imgdiff.py` — рендер старого кадра новой версией и сравнение (эпизод 001 16:9 —
  эталон, кадры в `out/ep001_psr_b1257/16x9/frames`, но у s1 сохранились только кадры 1–31).

## Соглашения

- Код и комментарии — по-русски, кратко, в стиле `spacekit/`. Скрипты идемпотентны, сцены строятся с нуля.
- Эпизод: `episodes/epNNN_<slug>/` — `facts.md`, `system.py`, `shots_9x16.py`, `script_9x16.json`,
  `music_cues.json`, `episode.json`, `edit_9x16_en.json` (генерирует `build_edit.py`; коммитить —
  воспроизводимость монтажа), `publish_en.md`. Выход — `out/epNNN_<slug>/9x16/`, пакет — `out/epNNN_<slug>/release/`.
- Номер и slug: `NNN = max(episodes/ep*) + 1`, трёхзначный, не переиспользуется (и у брошенных эпизодов).
  slug — `[a-z0-9_]`, ≤ 16 символов, по каталожному имени (`psr_j1748`, `trappist1`, `sgr_a`): лимит путей 260.
- Перед превью и перед финалом — `tools/check_episode.py <episode.json>`. После рендера, до сборки —
  `tools/framecheck.py <episode.json>` (битые кадры и разовые сбои рендера по скачкам размера PNG, PASS/FAIL).
  После сборки — `tools/qa.py <episode.json> en` (PASS/FAIL), релиз — `tools/release.py`.
- Перед финальным рендером — превью (pct=50) всех шотов + контактный лист (`tools/contact.py`) + проверка
  вспышек/таймингов (`tools/cues.py`: FLASH/EVENT из логов → pulses/risers). После — `editkit/verify_video.py`
  по ключевым кадрам (через `tools/qa.py`).
- Коммиты — по-русски, по одному логическому изменению.
